# 0.3: can Sveltia carry the Figure block?

**Question** (roadmap 0.3, PRD open question 4): is Sveltia's `registerEditorComponent` enough for a Figure block
(upload or choose an image, required alt text, caption, credit, licence, alignment, width, wrap, a preview with the
image), or do we need the fallback, a TipTap-style editor of our own?

**Answer: Sveltia is enough.** Tested 21 Nov 2026 in real Sveltia CMS 0.262.4 (the version korazonresearch.org pins),
running headless with its built-in `test-repo` backend, the real Cite block, and a prototype Figure block. Decision
pending Randal.

## What was tested, and what happened

| Need | Result | Evidence |
|---|---|---|
| Image upload inside a block's form | **Works.** "Drop an image file here or Browse / Paste Image". Browse opens Sveltia's media library, whose Upload button takes a new file | Uploaded a PNG; it was saved to `static/uploads/` in the same save as the page |
| Choose an existing image | **Works.** The same library lists the site's images | The seeded `mask.png` was offered |
| Required alt text | **Enforced.** Saving with Image and Alt text empty is refused: "2 fields have errors. Please correct them to save the entry." | Nothing was written |
| Caption, credit, licence, alignment, width, wrap | **Work.** Ordinary string, select, and boolean fields | All rendered with labels |
| Preview with the image, before it is published | **Works.** `toPreview(data, getAsset)` resolves the unpublished upload | Preview pane showed the uploaded image and its caption |
| What lands in the file | `{figure src:"/uploads/upload-me.png" \| alt:"…" \| caption:"A test figure, \"quoted\" \| piped" \| credit:"Lab"}` on its own line | Quotes and pipes escaped |
| Round trip of a figure | **Stable.** Reload, edit text elsewhere, save: the figure line is byte-for-byte the same | Compared before and after |
| Round trip of citations in real Sveltia | **Stable.** Opening and saving a page with an untouched body changes nothing. Editing the body changes only the edit and stale or missing `note:` values (the Cite block's own field). Code spans, `{citation endnote}`, unresolved works, tags, and option order are kept | Diffed the file before and after |

Sveltia's own source agrees. Its type definitions document field-level `media_folder` for editor components, and
`getAsset` searching those folders. Its test suite includes a `figure` component with an Image field whose preview
resolves an unpublished upload (`rich-text-preview.svelte.test.js`, "resolves an image in a component preview from
the component's media folder").

## What Sveltia can't do, and what to do instead

- **Write a second file.** A component returns only its own Markdown, so it can't write a separate provenance record
  per image. Carry the provenance fields (credit, licence, source) in the `{figure …}` tag, and have the host's build
  write or check the provenance records from the tags. This keeps "nothing hidden": the facts are in the page, and in
  the diff.
- **Stock photos.** The media library offers Pexels, Pixabay, Unsplash, and Lorem Picsum by default. Those send
  searches to third parties and bring in images without our provenance. Switch them off in the site's config before
  writers see them.
- **Validation messages** stay on screen after a required field is filled, until the next save. That's cosmetic, in
  Sveltia, not ours.
- **Empty optional fields.** On saving, Sveltia writes an empty optional front-matter field (`title: ''`). That's site
  config, not a block, but worth knowing when reading diffs.

## A bonus: real Sveltia in the demos

The `test-repo` backend, seeded with `<link rel="cms-seed-url" href="…/manifest.json">`, runs the whole CMS in the
browser's private storage: no sign-in, no server, nothing published. Sveltia calls this a demo site. The demos on
GitHub Pages could run real Sveltia with draft.inator's blocks on the sample site, beside or instead of today's
stand-in.

## Recommendation

1. Build the Figure block on Sveltia: `{figure …}` in the same option grammar as citation markers (`key:value`,
   `|` between options, quoting as citation.inator does), round-trip tested like Cite, unknown options kept.
2. Provenance in the tag; the build writes or checks the records.
3. Keep the TipTap fallback in the PRD as the plan if a later block (Table, perhaps) proves too much.
4. Add a real-Sveltia demo for the docs release.

The lab used to get these results (a seeded test site and Playwright scripts) can be added to `examples/` if it's
wanted again.
